# Software Stack

## Runtime Services

| Service | Location | Runtime | Purpose |
| --- | --- | --- | --- |
| Home Assistant | `home-assistant/config` | Docker image `ghcr.io/home-assistant/home-assistant:stable` | Device integrations and Home Assistant REST/WebSocket APIs |
| Backend | `backend/` | Python 3.11, FastAPI, Uvicorn | Auth, device registry, scenes, HA control, onboarding, Spotify, WebSocket events |
| Qt kiosk | `qt-frontend/` | C++17, Qt 6 Quick/QML | Native 800x480 touchscreen UI |
| voice-listener | `voice-pipeline/listener/` + `services/` | Python 3.11, FastAPI | Wake word, microphone capture, STT, NVIDIA voice pipeline |
| voice-intent | `voice-pipeline/intent/` | Python 3.11, FastAPI | Legacy text intent bridge to backend `/api/voice/command` |
| Spotify Connect | Compose `spotify-connect` | `giof71/librespot` | Local Spotify Connect speaker named `Vokrr` |
| Cloudflare Tunnel | Compose `cloudflared` profile | `cloudflare/cloudflared` | Optional HTTPS tunnel for backend only |

## Frontend/UI Stack

The production UI is a native Qt app:

- Qt 6.5+ Quick/QML
- Qt WebSockets for backend realtime events
- Qt Multimedia for local camera preview
- Resource-bundled SVG icons and room images
- Fullscreen kiosk launch through `scripts/start_qt_kiosk.sh`

Build:

```bash
cmake -S qt-frontend -B qt-frontend/build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build qt-frontend/build
```

## Home Assistant Usage

The backend uses:

- REST `GET /api/`
- REST `GET /api/states`
- REST `POST /api/services/{domain}/{service}`
- WebSocket `config/entity_registry/list_for_display`
- WebSocket `config/area_registry/list`
- WebSocket `config/device_registry/list`
- WebSocket `state_changed` and `entity_registry_updated` subscriptions

Vokrr clients do not call Home Assistant directly.

## Tuya Usage

There is no direct Tuya API provider implemented in the current codebase. Tuya devices should be paired into Home Assistant using Home Assistant's Tuya/local-tuya workflow, then imported into Vokrr as Home Assistant entities.

Local `.env` deployments may contain `TUYA_*` values, but the Python backend, Qt frontend, and voice pipeline do not read them at runtime.

## WebSocket/Event Flow

Backend WebSocket endpoint:

```text
ws://<backend-host>:8080/ws?token=<access_token>
```

Events sent to clients:

| Event | Payload |
| --- | --- |
| `snapshot` | Full rooms/devices snapshot |
| `device.updated` | One device after control or HA state change |
| `voice.status` | Voice UI state and message |
| `voice.command` | Legacy backend intent result |
| `scene.ran` | Scene execution result |

## Voice Stack

The active listener uses:

- Picovoice Porcupine for wake word detection
- `sounddevice` and NumPy for microphone frames
- `faster-whisper` for local STT
- NVIDIA hosted Llama-compatible chat completions for classification
- Home Assistant REST service calls for execution
- NVIDIA Magpie TTS through `nvidia-riva-client`
- `aplay` or `ffplay` for audio playback

The listener is one-shot: after wake word, it records one command for up to `VOICE_COMMAND_RECORD_SECONDS` seconds, processes it, and resets to wake-word mode.

## Camera Libraries

The Qt UI uses Qt Multimedia. OS-level camera support is provided by Raspberry Pi OS through libcamera/V4L2.

## System Services and Scripts

| --- | --- |
| `infra/systemd/vokrr-wifi.service` | Configures primary/secondary Wi-Fi through NetworkManager |
| `infra/systemd/vokrr-stack.service` | Starts/stops Docker Compose stack |
| `infra/systemd/vokrr-kiosk.service` | Starts the Qt kiosk |
| `scripts/phase0_setup.sh` | Installs packages, Docker, display/audio config, units |
| `scripts/start_qt_kiosk.sh` | Waits for display/backend and launches kiosk |
| `scripts/select_audio_output.sh` | Selects ALSA playback device and writes env file |
| `scripts/restart_audio_stack.sh` | Re-detects audio and recreates Spotify/listener services |
| `scripts/configure_wifi_networks.sh` | Creates/activates NetworkManager Wi-Fi profiles |
| `scripts/health_check.sh` | Manual service verification |
| `scripts/generate_ios_project.py` | Generates/updates the iOS Xcode project |
