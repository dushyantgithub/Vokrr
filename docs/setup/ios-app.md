# Vokrr iOS App

The native SwiftUI client lives in `ios/Vokrr/` and targets iOS 17 or newer. The checked-in Xcode project is generated by `scripts/generate_ios_project.py` and contains two targets:

- `Vokrr`: the iPhone app.
- `VokrrWidgets`: the small Health and medium Home widgets, including interactive device controls.

The app communicates only with the Vokrr backend. Home Assistant, AI provider, and Ultrahuman credentials remain server-side and are never generated into the app or widget bundle.

## Features

- Home dashboard, room detail, and live device control.
- Ultrahuman recovery, sleep, metabolic, movement, and vital metrics through `/api/health/dashboard`.
- Jarvis typed and spoken commands through `/api/voice/command`.
- Small Health and medium Home widgets backed by an App Group snapshot.
- Interactive widget device toggles using shared Keychain sessions and refresh-token rotation.
- WebSocket state updates, offline messaging, secure Keychain storage, custom fonts, Reduce Motion support, and privacy manifests.

## Configuration

Set the public HTTPS backend URL in the root `.env`:

```bash
IOS_DEFAULT_SERVER_URL=https://api.vokrr.com
```

Then regenerate the project:

```bash
python3 scripts/generate_ios_project.py
```

The generator reads only `IOS_DEFAULT_SERVER_URL`. It does not copy `UH_TOKEN`, `UH_ACCOUNT`, `UH_ACCESS_CODE`, or other backend secrets into iOS build settings.

## Apple Developer Setup

Before archiving, confirm these identifiers exist in the selected Apple Developer team:

- App ID: `com.vokrr.ios`
- Widget App ID: `com.vokrr.ios.widgets`
- App Group: `group.com.vokrr.shared`
- Keychain group: `$(AppIdentifierPrefix)com.vokrr.shared`

Enable the App Groups and Keychain Sharing capabilities for both targets. If the identifiers or team change, update `scripts/generate_ios_project.py` and both entitlement files, then regenerate the project.

## Build and Verify

Simulator Debug build:

```bash
xcodebuild -project ios/Vokrr/Vokrr.xcodeproj \
  -scheme Vokrr \
  -configuration Debug \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  build
```

Unsigned physical-device SDK validation:

```bash
xcodebuild -project ios/Vokrr/Vokrr.xcodeproj \
  -scheme Vokrr \
  -configuration Release \
  -destination 'generic/platform=iOS' \
  CODE_SIGNING_ALLOWED=NO \
  build
```

For local visual QA without a backend session, pass `-VOKRRPreviewMode`. Optional QA arguments are `-VOKRRSkipSplash` and `-VOKRRPreviewTab Health|Jarvis|Settings`.

## Archive and Deploy

1. Open `ios/Vokrr/Vokrr.xcodeproj` in Xcode.
2. Confirm automatic signing succeeds for both `Vokrr` and `VokrrWidgets`.
3. Select **Any iOS Device (arm64)** and run **Product > Archive**.
4. Validate the archive in Organizer, then upload it to App Store Connect.
5. Complete the App Privacy answers so they remain consistent with `PrivacyInfo.xcprivacy`, provide a privacy-policy URL, and add the required App Store screenshots.
6. Test the uploaded build in TestFlight against the production HTTPS backend, including speech permissions, token refresh, remote device control, background widget refresh, and Ultrahuman data freshness.

Release signing and App Store upload require the Apple Developer account’s distribution certificate and provisioning access; these are intentionally not stored in the repository.
